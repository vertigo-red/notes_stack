# Роль Ansible `notes_stack`

Устанавливает Docker Engine и Compose plugin на **Ubuntu Server 22.04**, настраивает
ротацию JSON-логов, получает неизменённый исходный код Notes, копирует файлы
контейнеризации из роли и запускает приложение с PostgreSQL. Роль рассчитана
на отдельную VM, доступную по SSH с `sudo`.


## Поведение

1. До включения UFW добавляет разрешение на заданный SSH-порт. После этого
   включает политику `deny incoming` и `allow outgoing`.
2. Убирает *установленные* конфликтующие пакеты Ubuntu, подключает официальный
   подписанный apt-репозиторий Docker и ставит Engine, CLI, Buildx, Compose plugin.
3. Сохраняет прочие ключи существующего `/etc/docker/daemon.json`, задаёт
   `log-driver=json-file`, `max-size=10m`, `max-file=3`, перезапускает Docker
   только если настройки изменились. Те же настройки дублируются в Compose
   для приложения и БД: ранее созданные контейнеры получают их после
   обычного обновления конфигурации Compose.
4. Клонирует `bfg-group/test_app` в `/opt/test_app` (URL и ref изменяемы),
   копирует `Dockerfile`, `.dockerignore`, шаблон Compose и локальный `.env`.
   Исходники `app/` не меняет. `.env` доступен только root (`0600`);
   Ansible не печатает секретный шаблон и вывод задачи запуска Compose.
5. Обновляет существующие контейнеры **того же Compose project**
   `test_app` при изменении конфигурации; удаляет orphan-контейнеры
   проекта без удаления томов. Отдельные старые контейнеры удаляются только
   по именам в `notes_legacy_container_names`. Остальные работающие
   контейнеры остаются вне управления ролью; cron ниже затрагивает
   остановленные контейнеры всего хоста.
6. Задаёт ежедневный cron от root:
   `docker system prune -f` в 03:15 с блокировкой от параллельного запуска.
   Команда касается **всего Docker-хоста**: удаляет остановленные контейнеры,
   неиспользуемые сети и образы. Без `--volumes` именованный том PostgreSQL
   не удаляется.

## Сетевой доступ

Приложение слушает `127.0.0.1:8000` на VM, PostgreSQL на хост не публикуется.
Снаружи разрешён только SSH (по умолчанию порт 22). Для проверки с контроллера:

```bash
ssh -N -L 18000:127.0.0.1:8000 ubuntu@<IP_VM>
# В другом терминале: curl -f http://127.0.0.1:18000/readyz
```

UFW использует правила iptables в Ubuntu, но Docker может обходить UFW для
публикуемых портов. Поэтому порт приложения *намеренно* привязан к loopback.
Не заменяйте адрес в шаблоне Compose на `0.0.0.0` без отдельного контроля
`DOCKER-USER` или внешнего reverse proxy. На хосте с уже опубликованными
портами чужих Docker-контейнеров UFW сам по себе их не закрывает.

## Переменные

**Все пользовательские настройки и значения по умолчанию** находятся в
[`defaults/main.yml`](defaults/main.yml). Главные:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `notes_postgres_password` | пусто | Обязательный секрет из Ansible Vault, от 16 символов |
| `notes_app_git_url`, `notes_app_git_version` | upstream, `master` | Источник и ref приложения; для production закрепите SHA |
| `notes_deploy_dir`, `notes_compose_project_name` | `/opt/test_app`, `test_app` | Каталог проекта и имя Compose; определяет имя тома `test_app_pgdata` |
| `notes_app_port` | `8000` | Порт только на loopback VM |
| `notes_ssh_port`, `notes_ssh_allowed_cidrs` | `22`, `[any]` | Установите действительный SSH-порт и допустимые IP до включения UFW |
| `notes_docker_log_max_size`, `notes_docker_log_max_file` | `10m`, `3` | Ротация логов daemon и контейнеров |
| `notes_legacy_container_names` | `[]` | Имена старых самостоятельных контейнеров, которые нужно убрать |
| `notes_prune_hour`, `notes_prune_minute` | `3`, `15` | Расписание ежедневной очистки |

Пароль ограничен безопасными для однострочного Compose `.env` символами.

`notes_stop_grace_period_seconds` должен быть строго больше
`60 + notes_shutdown_delay_seconds`: `/slow` допускает 60 секунд,
приложение затем выдерживает штатную паузу (3 с по умолчанию).

## Проверка

В роли есть `tasks/verify.yml`: HTTP readiness, health обоих контейнеров,
UID 10001, параметры логирования, отсутствие публикации порта БД и привязка
приложения к loopback. Запускается из соседнего проекта через `verify.yml`.
Это проверка **после развёртывания**.
